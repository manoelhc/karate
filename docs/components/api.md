# COMP-API — project API and shared application service

Owner: backend implementer. TASK-003b1 implements REQ-001 and portions of
PLAT-TENANT/RBAC/OAUTH/AUDIT/I18N. Rust 1.99.1; `crates/karate-api` contains
identity, PostgreSQL service, HTTP transport and a runnable binary. No assessment
traffic or model execution is introduced. The backend-engineer workflow applies.

## Contract and authority

Bearer tokens are signed RS256 access JWTs with `typ=at+jwt`, issuer, audience,
subject, iat and exp. A configured public JWKS file or [trusted discovery snapshot](identity-refresh.md) supplies keys; key IDs,
algorithm, signature, issuer, audience, expiry and optional nbf are validated by
jsonwebtoken plus bounded claims checks. The snapshot has an absolute expiry and
fails closed after it. No discovery from token-supplied URLs, auth bypass or
client-controlled role/tenant claim. Browser authorization-code/PKCE and sessions remain separate work; discovery and
bounded JWKS refresh are an opt-in resource-server capability.

The shared ProjectService authenticates before acquiring a DB connection or
resolving current membership. A transaction sets tenant/issuer/subject locally,
reads membership, calls core policy, and performs parameterized scoped queries.
All transports must call this service. No authorization is cached. RLS rechecks
membership for every data statement; concurrent revocation is observed on the
next statement/request, not retroactively after a committed operation.

POST creates a caller-identified UUID project idempotently: same tenant/id/name
returns the existing project; a different name conflicts. PATCH uses expected
revision and increments it atomically; a stale writer gets CONFLICT. GET lists
1–100 rows (default 25), ordered by UUID with an exclusive `after` cursor and
`next_cursor` only when more rows exist. GET by ID never exposes another tenant.
No delete endpoint exists in this slice. Successful create/update and its audit
event commit together; read-only retries do not create mutation audit events.

## Data and operations

Migration 0002 adds append-only tenant-scoped project audit records. The runtime
cannot update/delete audit rows or directly provision tenants/memberships.
Existing membership administration uses the [membership component](membership.md)
and identity-bound enrollment uses [invitations](invitations.md)
and narrow database capabilities; direct runtime membership writes remain denied. A privileged
bootstrap process must create tenants and issuer/subject memberships explicitly;
no first-login auto-admin. Bodies max 8 KiB, credentials max 8 KiB, list max 100,
pool max 8, acquire timeout 2s, SQL timeout 3s, transaction idle timeout 5s.
Runtime connections must be Unix sockets; TCP is rejected until verified TLS
support is added. PostgreSQL remains durable/shared, not process-local state.
The configured role must not own customer tables or have superuser/BYPASSRLS.

API binds loopback only; a terminating proxy and operational review are required
for deployment. Non-loopback bind settings currently fail startup. Missing or invalid configuration stops
startup. JWKS is a public configuration file, never a secret/keypair file; the
loader rejects oversized input. Credentials/DB URL never appear in errors/logs.
HTTP errors are closed codes with localized en/pt-BR messages and remediation,
Content-Language and no provider internals. Request IDs are generated by the
service, not accepted as authorization. No raw audio/target data is handled.

File-mode key snapshots are immutable process configuration with explicit expiry;
rotation in that mode means replacing the file and restarting. Discovery mode
refreshes a bounded public snapshot without caching tenant authority. No cached membership or
project-summary cache is introduced. Cache-first summary reads, global tenant
rate limits, OTel export, containers, TLS and complete deletion/retention policies
remain mandatory future work. Graceful process shutdown drains accepted requests.

## Verification plan

Use ephemeral RSA keys generated during tests; no private key fixture is committed.
Test real signed valid/expired/forged/wrong-algorithm/audience/issuer tokens, missing
claims, unknown kid and expired JWKS. Tests are a local issuer fixture, not proof
of a commercial provider or complete OIDC sign-in integration.
Run real HTTP routes and direct service calls against an isolated PostgreSQL
cluster with a nonsuperuser runtime. Cover two tenants sharing project IDs,
viewer denial, malformed bodies, list limits/cursors, concurrent revision writes,
idempotent creates, revoked membership, audit atomicity, pool reuse and outages.
All executable API/library files require their own >90% line/branch evidence;
missing data blocks the gate rather than borrowing the core library percentage.

## Scoped credential authentication

[API keys](api-keys.md) now authenticate through a bounded credential lookup and
AWS-LC verifier comparison before membership resolution. The resulting typed
restriction reduces authority by tenant, scopes and creator membership revision.
JWT remains the interactive control-plane credential. Keys cannot manage keys,
memberships or invitations. Lifecycle changes and audit are atomic.
